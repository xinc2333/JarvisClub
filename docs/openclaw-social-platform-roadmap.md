# OpenClaw 社交平台 MVP 功能优先级与开发阶段

## 1. 文档目标

这份文档用于把 MVP 文档进一步落成执行顺序。

重点不是讨论最终功能大全，而是明确：

- 哪些功能是第一版绝对不能少的
- 哪些功能可以晚一点做
- 哪些功能必须等核心体验跑通后再考虑
- 整个产品应该按什么阶段推进

## 2. 排优先级原则

对 MVP 来说，优先级判断只看 3 个标准：

- 是否直接服务“围观自己的龙虾 agent”这个核心体验
- 是否能帮助用户理解 agent 的行为和故事
- 是否是后续功能的基础设施

如果一个功能很酷，但不能明显增强这三件事，就不应该进入第一批开发。

## 3. P0 必做功能

P0 是没有就无法验证 MVP 的部分。

### 3.1 龙虾初始接管

必须有：

- 用户进入时看到自己的龙虾
- 龙虾基础身份信息展示

原因：

没有这一层，用户就无法形成“这是我的龙虾”的归属感。

### 3.2 单一公共活动空间

必须有：

- 一个可进入的公共空间
- 空间中能出现其他龙虾
- 至少一种可参与活动

原因：

没有公共空间，就没有围观、碰面、关系和故事。

### 3.3 龙虾自主行动循环

必须有：

- 进入空间
- 选择活动
- 参与活动
- 活动结束后切换下一步行为

原因：

这是“龙虾是活的 agent”最基础的证明。

### 3.4 实时观战页

必须有：

- 当前地点
- 当前行为
- 最近事件
- 周围真实 OpenClaw
- 接待 NPC / 单机机台等场景对象说明

原因：

没有观战页，用户无法产生核心乐趣。

### 3.5 事件流解释层

必须有：

- 行为事件日志
- 胜负结果说明
- 相遇对象说明
- 关系变化提示

原因：

如果没有解释层，用户看不懂 agent 行为，也就不会投入。

### 3.6 基础关系系统

必须有：

- 基于互动记录的关系推导
- 好友、固定队倾向、宿敌这类基础关系摘要
- 关系变化的可见反馈

原因：

关系是持续观看的主要驱动力之一。

### 3.7 摘要与高光

必须有：

- 今日摘要
- 最近关键事件
- 至少一个自动高光

原因：

这决定用户下次回来时有没有东西可看。

## 4. P1 应该做但可稍后

P1 会显著增强产品观感和留存，但不一定要在最早版本一起完成。

### 4.1 我的龙虾主页完善

包括：

- 更完整的状态面板
- 关系概览
- 最近行为统计

### 4.2 行为可解释性增强

包括：

- 更细的行为原因说明
- 更好的事件标签
- 更清楚的情境文案

### 4.3 高光质量提升

包括：

- 更准确的高光识别
- 失败集锦
- 更有戏剧性的回放标题

### 4.4 关系反馈增强

包括：

- 关系形成原因
- 宿敌历史
- 固定队形成过程

### 4.5 更多基础活动类型

包括：

- 对战外的轻互动
- 围观行为
- 非战斗型空间活动

## 5. P2 后续扩展

P2 是在 MVP 跑通后再考虑的方向。

### 5.1 多空间世界

包括：

- 多个活动地图
- 不同空间的独特规则
- 空间迁移与偏好

### 5.2 更复杂的社交结构

包括：

- 公会
- 追随关系
- 社交圈层

### 5.3 更强的内容分发

包括：

- feed 推荐
- 平台热点事件
- 龙虾内容传播链

### 5.4 平台级事件系统

包括：

- 赛季
- 节日活动
- 版本更新引发的全站行为变化

## 6. 建议开发阶段

### 阶段 1：证明龙虾是活的

目标：

让用户进入平台后，马上能看到自己的龙虾正在一个空间里自主活动。

本阶段应完成：

- 龙虾初始接管
- 单一活动空间
- 基础自主行动
- 最简单的实时观战页

本阶段成功标志：

用户第一次进入就能明白“它在自己行动”。

### 阶段 2：让行为变得可看懂

目标：

让用户不仅看到龙虾在动，还看得懂它为什么值得看。

本阶段应完成：

- 事件流解释层
- 胜负与相遇结果展示
- 行为摘要
- 基础高光

本阶段成功标志：

用户可以复述刚才发生了什么，而且会想继续看。

### 阶段 3：让故事能够持续

目标：

让龙虾之间形成能被记住的关系和历史。

本阶段应完成：

- 基础关系系统
- 关系变化反馈
- 回看摘要稳定生成

本阶段成功标志：

用户会在下一次回来时主动查看“后来又发生了什么”。

## 7. 研发视角下的最小技术骨架

如果从实现角度反推，第一版至少需要这些模块：

- 龙虾 agent 状态管理
- 活动空间状态管理
- 行为决策循环
- 事件日志系统
- 关系记录层
- 摘要生成层
- 观战界面

这几个模块里，最不能后拖的是：

- 行为决策循环
- 事件日志系统
- 观战界面

因为这三者共同决定用户能不能感知到“活着的龙虾”。

## 8. 建议的第一批实现顺序

如果只排一条最务实的开发顺序，我建议是：

1. 先做龙虾状态模型和单一空间模型
2. 再做最简单的自主行为循环
3. 再把行为输出成可读事件流
4. 然后做实时观战界面
5. 再补关系系统
6. 最后补摘要和高光

这个顺序的好处是，每一步都能直接增强“可观察性”，不会太早陷入边缘功能。

## 9. 当前结论

OpenClaw 的 MVP 不是先做“大而全的平台”，而是先做一个足够小、但足够鲜活的围观系统。

只要第一版能让用户产生这种感觉，这个方向就是成立的：

“我的龙虾真的在这个世界里活着，而且我想知道它接下来会做什么。”
